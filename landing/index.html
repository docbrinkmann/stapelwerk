01The 2 a.m. mistake

The classic media-stack failure: the VPN is next to your torrent client, not around it.

A torrent client running beside a VPN container looks safe — until the tunnel drops and your real IP leaks. It's the most common wiring mistake in self-hosted media stacks, and you usually find out the hard way. Stapelwerk encodes the fix once and verifies it on every build:

  • The download client runs inside the VPN container's network namespace (network_mode: service:gluetun), publishes no ports of its own, and depends on the gateway.
  • Gluetun gets cap_add: [NET_ADMIN] + /dev/net/tun and owns the routed ports.
  • If a build has a download client and a VPN but isn't routed, Stapelwerk raises a hard "VPN leak" error with the exact fix — before deploy, not at 2 a.m.

It isn't advice that looks right — an LLM can type that. It's a checked, versioned, runnable artifact: the wiring rules live in code and are enforced on every single build.

03The €29 verified deploy

A signed proof that your stack is deploy-safe — by construction.

One time, per stack: Stapelwerk generates an ed25519-signed report attesting what was actually verified in your compose — a provenance artifact you can keep, share, and check against our published public key.

  • Kill-switch confined: the download client cannot reach the network except through the VPN — no real-IP leak if the tunnel drops.
  • No datastore exposed on the host network — your Postgres / Redis / Mongo ports stay internal.
  • Datastores keep their data — stateful services have volumes; no default or empty secrets; images pinned.
  • You keep the compose and run it yourself — free forever. The €29 buys the signed proof, not a hosted deploy. We never hold your SSH keys.

* Honest scope: the report attests the configuration is safe by construction — it names exactly what was checked and marks everything else "not checked". It is not a promise about software you install later or CVEs discovered tomorrow. On local-socket deploys you can additionally run a runtime attestation that boots the stack and confirms traffic actually dies when the VPN drops.

05FAQ

Common questions

What is Stapelwerk?
Stapelwerk is a guided Docker stack composer for self-hosters. It composes a media server stack (Jellyfin, Sonarr, Radarr, Prowlarr, qBittorrent, Gluetun), checks compatibility, ports, resources and the VPN kill-switch before deploy, and exports a clean docker-compose.yml you can run anywhere.
How does Stapelwerk verify the VPN kill-switch?
By construction: the download client runs inside the VPN container's network namespace (network_mode: service:gluetun), publishes no ports of its own and depends on the gateway. If a stack has a download client and a VPN but is not routed through it, Stapelwerk raises a hard VPN-leak error before deploy.
What does the €29 verified deploy include?
A one-time, per-stack ed25519-signed report attesting what was verified in your compose: the kill-switch confinement plus a safety audit — no datastore exposed on the host network, volumes for stateful services, no default secrets, pinned images. Verifiable with our published public key. The compose itself stays free.
