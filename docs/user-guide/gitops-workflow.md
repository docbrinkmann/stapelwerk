# GitOps Workflow Guide

**Last Updated:** 2025-12-05  
**Spec Reference:** Phase 4.2 - User Documentation

---

## Overview

Stapelwerk integrates with ArgoCD to provide GitOps-based deployments. This enables:

- **Declarative Configuration** - Define desired state in Git
- **Automated Sync** - Automatic deployment when Git changes
- **Self-Healing** - Automatic drift correction
- **Version Control** - Full audit trail of changes

---

## Prerequisites

Before using GitOps features:

1. **ArgoCD Installation** - ArgoCD must be installed in your cluster
2. **Git Repository** - A repository for your manifests
3. **Authentication** - ArgoCD credentials configured in Stapelwerk

---

## Setting Up GitOps

### Step 1: Connect ArgoCD

1. Navigate to **Settings** → **Integrations**
2. Click **Add ArgoCD Server**
3. Enter your ArgoCD server URL
4. Provide authentication token
5. Test connection and save

### Step 2: Configure Git Repository

1. Go to **GitOps** → **Repositories**
2. Click **Add Repository**
3. Enter repository URL (HTTPS or SSH)
4. Add credentials if private
5. Verify connectivity

### Step 3: Create Application

1. Navigate to **GitOps** → **Applications**
2. Click **Create Application**
3. Fill in configuration:

| Field | Description |
|-------|-------------|
| Name | Application name |
| Project | ArgoCD project (default: `default`) |
| Repository | Git repository URL |
| Path | Path to manifests in repo |
| Target | Kubernetes cluster and namespace |

## Common Operations

### Sync Application

Force synchronization with Git state:

```
1. Select application
2. Click "Sync" button
3. Choose options:
   - Prune: Remove resources not in Git
   - Force: Override existing resources
   - Dry Run: Preview changes only
4. Confirm sync
```

### Rollback

Revert to a previous state:

```
1. Select application
2. Go to "History" tab
3. Select target revision
4. Click "Rollback"
5. Confirm rollback
```

### Delete Application

Remove application from ArgoCD:

```
1. Select application
2. Click "Delete" button
3. Choose:
   - Cascade: Delete Kubernetes resources too
   - Non-cascade: Keep K8s resources
4. Confirm deletion
```

## Sync Policies

### Manual Sync

Default mode - sync only when triggered manually.

**Use when:**
- Production environments
- Requiring approval gates
- High-risk changes

### Auto Sync

Automatic sync when Git changes detected.

**Configuration:**
```yaml
syncPolicy:
  automated:
    prune: true      # Remove deleted resources
    selfHeal: true   # Fix drift automatically
```

**Use when:**
- Development environments
- Rapid iteration needed
- Low-risk applications

### Self-Heal

Automatically revert manual changes to match Git.

**Behavior:**
1. Detects drift from desired state
2. Automatically applies correct state
3. Logs drift event

## Multi-Environment Setup

### Using ApplicationSets

Deploy to multiple environments from one definition:

```yaml
# Generated by Stapelwerk
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: my-app
spec:
  generators:
    - list:
        elements:
          - env: dev
            namespace: app-dev
          - env: staging
            namespace: app-staging
          - env: production
            namespace: app-prod
  template:
    metadata:
      name: 'my-app-{{env}}'
    spec:
      source:
        repoURL: https://github.com/org/repo
        path: 'overlays/{{env}}'
```

### Environment Promotion

Promote changes through environments:

1. Changes merged to `main` branch
2. Auto-sync to `dev` environment
3. Manual promotion to `staging`
4. Approval required for `production`

## Troubleshooting

### "OutOfSync" Status

**Causes:**
- Git changes not yet applied
- Drift from desired state
- Resource comparison issues

**Resolution:**
1. Check sync status details
2. Review diff between live and desired
3. Trigger manual sync if needed

### "Degraded" Health

**Causes:**
- Pods failing to start
- Resource constraints
- Configuration errors

**Resolution:**
1. Check resource events
2. View pod logs
3. Verify resource limits

### "Unknown" Status

**Causes:**
- ArgoCD can't reach cluster
- Resource not supported
- Network issues

**Resolution:**
1. Verify cluster connectivity
2. Check ArgoCD server logs
3. Validate resource definitions

### Sync Fails

**Causes:**
- Invalid manifests
- Permission denied
- Resource conflicts

**Resolution:**
1. Review sync error message
2. Validate YAML syntax
3. Check RBAC permissions

## Best Practices

### Repository Structure

```
repo/
├── base/                 # Base configurations
│   ├── deployment.yaml
│   ├── service.yaml
│   └── kustomization.yaml
└── overlays/
    ├── dev/
    ├── staging/
    └── production/
```

### Naming Conventions

- **Applications:** `{app-name}-{environment}`
- **Namespaces:** `{app-name}-{environment}`
- **Branches:** `main`, `develop`, `release/*`

### Security

1. **Least Privilege** - Minimal RBAC permissions
2. **Secrets Management** - Use Sealed Secrets or External Secrets
3. **Audit Logging** - Enable ArgoCD audit logs

### Change Management

1. **Pull Requests** - Review all changes
2. **Branch Protection** - Require approvals
3. **Automated Testing** - Validate manifests in CI
